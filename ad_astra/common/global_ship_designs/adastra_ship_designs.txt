# Ad Astra - designs de vaisseaux sous-luminiques (aucun module d'hyperpropulsion)
# Livrés par le programme spatial ; l'empire verrouillé ne génère pas de designs automatiques.

# 16/08, LA VRAIE CAUSE DU CHANTIER VIDE.
#
# is_special_buildable ne suffisait pas : les plans etaient bien dans la liste
# de l'empire (verifie dans la sauvegarde) et le chantier ne proposait rien.
#
# Chaque taille de vaisseau du jeu de base declare
# « required_component_set = ftl_components ». Un design dont cet emplacement
# reste vide n'est pas un design valide : le moteur accepte de le faire naitre
# par evenement, mais refuse de le proposer a la construction. Nos coques
# sous-luminiques n'avaient rien dans cet emplacement, par construction.
#
# Le jeu de base a exactement la piece qu'il faut : EMPTY_DRIVE, « NON-FTL
# DRIVE », sans prerequis technologique, membre du jeu ftl_components et
# « upgrades_to = HYPER_DRIVE_1 ». C'est la cale vide qu'on met en attendant de
# savoir plier l'espace. Elle remplit l'emplacement sans rien permettre.

# 16/08 : is_special_buildable = yes.
#
# create_ship_design fait entrer le plan dans la liste des designs de l'empire,
# mais un design GLOBAL n'apparait pas pour autant au chantier : le jeu ne
# propose a la construction que les designs marques comme constructibles.
# Sans cette ligne, le joueur voyait ses trois plans dans sa liste et la
# section civile du chantier restait vide - releve en jeu le 16/08.
# Champ documente dans common/global_ship_designs/000_documentation.txt,
# employe par le jeu de base sur les vaisseaux Cybrex et les bio-plateformes.

# 1.2 - vaisseau de colonisation sous-luminique.

# donc je ne peux pas faire de colonisateur, et meme si je construis un complexe
# d'habitat je ne peux pas y installer de population ».
