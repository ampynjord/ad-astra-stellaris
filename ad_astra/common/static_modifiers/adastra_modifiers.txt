# 1.2 : les ressources qui n'existent pas encore ne se consomment pas non plus.
#
# Poses et retires par adastra.11 (pulsation mensuelle) en fonction des technos,
# pas des ages : c'est l'invention qui cree la ressource, pas le calendrier.
# Sans ca, l'empire paierait une facture d'electricite mille ans avant d'avoir
# l'electricite, et un deficit permanent bloquerait toute la partie.

# Tant que le Reseau electrique n'est pas connu : aucun entretien energetique.
# Remplace la reduction par age qui figurait dans la situation - une reduction
# de 70 % laissait 30 % d'une facture qu'on ne pouvait pas payer.
# Note : planet_districts_energy_upkeep_mult figurait ici et n'avait AUCUN effet
# sur l'entretien des districts, verifie en jeu le 13/08 (district agricole 0,30,
# minier 0,20, urbains 0,60 toujours factures). L'entretien des districts est
# desormais traite la ou il ne peut pas etre ignore, dans la definition du
# district elle-meme - voir common/districts/zzz_adastra_district_ages.txt.
# Ce modificateur ne couvre plus que les BATIMENTS, ou il fonctionne.
#
# 15/08 - CORRECTION. Il portait planet_structures_upkeep_mult, qui vise TOUTES
# les ressources et pas seulement l'energie. Consequence vue en jeu : le
# Monument des ancetres, dont l'entretien bascule en minerais faute
# d'electricite, se faisait raboter ces minerais de 90 % - « Base 1.00,
# Un monde sans courant -100 % » affichait 0,10 minerai. Les batiments
# d'epoque etaient donc quasiment gratuits, et l'infobulle annoncait une
# coupure de courant sur une facture en cailloux.
#
# Le jeu de base expose une variante par ressource : planet_structures_
# energy_upkeep_mult. C'est celle qu'il fallait. Elle ne touche que l'energie,
# donc l'entretien de substitution en minerais est paye plein pot.
#
# Le plafond du moteur a -90 % s'applique toujours : un batiment VANILLA
# construit avant l'electricite paiera 10 % de sa facture energetique. Nos
# batiments d'epoque, eux, sont a zero exact parce que leur definition ne
# comporte aucune ligne « energy » tant que l'electricite manque.
adastra_pre_electric = {
	planet_structures_energy_upkeep_mult = -1
}

# Tant que la Machine a vapeur n'est pas connue : personne n'achete de biens
# manufactures, parce que personne n'en fabrique. La Manufacture, debloquee par
# cette meme techno, est le premier atelier qui produit en serie.
#
# 15/08 - EMPILEMENT DES PLAFONDS. Chaque multiplicateur d'entretien est
# plafonne a -90 % separement. Deux lignes ne suffisaient donc pas : il restait
# 10 % d'une facture en biens de consommation qui ne devraient pas exister, et
# le pansement du country_type (production forfaitaire) la couvrait en
# sur-corrigeant - la barre affichait « 89 (+1) » a l'age de pierre.
#
# Le pari, verifiable en jeu : les plafonds s'appliquent a chaque
# multiplicateur AVANT multiplication, pas a leur somme. En cumulant le
# multiplicateur global des emplois avec celui de CHAQUE categorie d'emploi,
# le residu passe de 10 % a 1 %, soit 0,00 a l'affichage. Si le moteur les
# additionne au contraire (-4300 % ramene a -90 %), rien ne change et le
# pansement du country_type devra revenir.
#
# La liste vient de la localisation du jeu de base, puis a ete TAILLEE d'apres
# error.log : dix-huit de ces noms existent en localisation mais pas comme
# modificateurs, et le moteur ecrivait « Invalid modifier » pour chacun a
# chaque lancement. Il ne rejetait que la ligne fautive, pas le bloc, mais un
# journal d'erreurs propre est ce qui rend les rapports de bug exploitables.
#
# 15/08, deuxieme passe. L'empilement a marche pour les EMPLOIS : leur ligne
# est tombee a zero. Il reste 0,12 par mois, et l'infobulle du jeu designe le
# coupable sans ambiguite - « Pops : 0.12 ». Ce residu ne vient pas d'un emploi
# mais du NIVEAU DE VIE, qui pose un entretien forfaitaire par categorie de pop
# (pop_category_*_consumer_goods_upkeep_add). Un forfaitaire ne se supprime pas
# avec un pourcentage : -90 % de 0,25 fait toujours 0,025, et multiplie par
# cinq cents pops, ca draine.
#
# On l'annule donc a la source, avec le meme forfaitaire en negatif. Les
# valeurs sont celles de « Conditions de vie normales », le niveau de vie par
# defaut : dirigeants 1,0 - specialistes 0,5 - ouvriers 0,25 - civils 0,25.
#
# Les multiplicateurs ne peuvent pas annuler cette facture : Stellaris les
# plafonne a -90 %. Les annulations sont donc forfaitaires, pour le niveau de
# vie et pour les emplois effectivement crees avant la Machine a vapeur.
adastra_pre_manufacture = {
	pop_category_rulers_consumer_goods_upkeep_add = -1
	pop_category_specialists_consumer_goods_upkeep_add = -0.5
	pop_category_workers_consumer_goods_upkeep_add = -0.25
	pop_category_civilians_consumer_goods_upkeep_add = -0.25
	# 21/08/2026 : ce modificateur n'existe pas en 4.4. Les dirigeants sont
	# deja couverts par pop_category_rulers_consumer_goods_upkeep_add.
	planet_bureaucrats_consumer_goods_upkeep_add = -2
	planet_entertainers_consumer_goods_upkeep_add = -1
	planet_enforcers_consumer_goods_upkeep_add = -1
	planet_researchers_consumer_goods_upkeep_add = -1
	planet_physicists_consumer_goods_upkeep_add = -1.5
	planet_biologists_consumer_goods_upkeep_add = -1.5
	planet_engineers_consumer_goods_upkeep_add = -1.5
}

# LE CONSEIL DES ANCIENS
#
# Pose le 15/08 apres relevé en jeu : a l'Age de pierre, l'unite etait en
# DEFICIT PERMANENT. Production 3,00 par mois, consommation 3,60, toute
# imputee a la ligne « Personnalites » - l'entretien des dirigeants. La reserve
# de depart fondait a vue d'oeil et rien, dans une civilisation confinee, ne
# pouvait la reconstituer : ni traditions, ni edits, ni batiments d'unite avant
# plusieurs ages.
#
# Le jeu de base facture ses dirigeants en unite parce qu'il les suppose
# encadres par une administration. Une chefferie n'a pas d'administration : le
# chef vit parmi les siens, le conseil se tient autour d'un feu, et cela ne
# coute a la communaute que le temps qu'on y passe. L'entretien tombe donc au
# quart tant que dure le confinement.
#
# Retire a l'emergence, comme les deux autres : voir adastra.15.
# 15/08, correction le soir meme : la premiere version portait
# « mod_leaders_upkeep_mult ». Le prefixe mod_ appartient a la LOCALISATION et
# au nom du fichier d'icone, jamais au modificateur lui-meme. Le moteur ignorait
# donc la ligne en silence - d'ou le « ? » a la place de l'icone, seul indice
# visible, et une unite toujours en deficit. Le vrai nom est leaders_upkeep_mult,
# celui qu'emploie deja chaque etape de la situation.
#
# L'etape d'age applique -0,70 de son cote. Les deux s'additionnent et butent
# sur le plafond du moteur a -0,90 : les dirigeants coutent un dixieme.
#
# 15/08, deuxieme correction. Un seul modificateur pour dix ages, toujours a la
# meme valeur : « il est la tout le temps et a la meme valeur ». Reproche juste,
# et pire que ca - les etapes de la situation reduisent DEJA l'entretien des
# dirigeants, de -0,70 a l'age de pierre a zero a l'age spatial. Un -0,70 fixe
# par-dessus poussait le total au plafond du moteur (-0,90) a tous les ages
# jusqu'a la vapeur : la degressivite prevue par les etapes ne se voyait nulle
# part.
#
# Trois paliers maintenant, qui se remplacent l'un l'autre et portent chacun le
# nom de ce qu'ils decrivent. Total obtenu, etape comprise :
#
#   pierre -0,90 · bronze -0,90 · fer -0,85     Le conseil des anciens
#   medieval -0,90 · renaissance -0,80 · vapeur -0,70   La cour et ses obliges
#   industriel -0,85 · machine -0,75 · atome -0,70 · spatial -0,60
#                                               Une administration naissante
#
# La courbe descend sans jamais lacher : l'unite reste positive parce que la
# production de base, elle, monte d'age en age.
adastra_council_of_elders = {
	leaders_upkeep_mult = -0.25
}

adastra_court_and_retinue = {
	leaders_upkeep_mult = -0.4
}

adastra_young_administration = {
	leaders_upkeep_mult = -0.6
}
